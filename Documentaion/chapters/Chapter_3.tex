\subsection{Why Two Distinct Neural Network Architectures?}
The main purpose of the proposed system is to diagnose grapevine diseases by analyzing their leaves. While the training dataset consists of single leaf images labeled with different disease classes. In real-world monitoring scenarios, the input images captured by camera contain multiple leaves in single frame. Therefore, training model with single leaf images to infer full frame is not effective. To address this, the system uses two distinct neural network architectures. One to localize and extract the target leaf regions from the image frame. The other to diagnose the disease symptoms on the extracted leaves. 
    

Additionally, the leaf localization and disease classification tasks have different characteristics requiring specific architectures and training strategies. By separating these tasks into two specialized models, each can be optimized for its specific task. The complete deployment pipeline of integrating these two domain specific models is explained in Section~\ref{sec: four_stage_pipeline}, with detailed model architectures in Sections~\ref{sec:espdet_pico} and~\ref{sec:mobilenetv2}.




\subsection{Four-Stage Pipeline Architecture}
\label{sec: four_stage_pipeline}

The disease detection system is implemented in a four-stage pipeline deployed on ESP32-S3 microcontrollers, as illustrated in Figure~\ref{fig:system_architecture}.

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.6\linewidth]{images/chapter3/four_stage_edgeAI_pipeline.png}

    \caption{Four-stage edge AI pipeline for grape leaf disease detection.}
    \label{fig:system_architecture}
\end{figure}

\textbf{Stage 1: Image Acquisition} - An OV3660 camera module capture grapevine images at VGA resolution (640$\times$480). This module is designed to receive parallel video data signals, and its bus supports an 8-bit ~ 16-bit DVP image sensor, with clock frequency of up to 40 MHz\cite{esp32s3_datasheet}.


\textbf{Stage 2: Leaf Localization} - A YOLO-based detection model (ESPDet-Pico) localizes individual grape leaves within the captured frame. This stage identifies and crops leaf, the regions of interest. The ESP-optimized model architecture and its training procedure are detailed in Section~\ref{sec:espdet_pico}.

\textbf{Stage 3: Disease Classification} - The detected leaves at stage 2 are resized and classified by a MobileNetV2 model trained on different classes of grape disease single leaf images. The details of this model training, quantization, and evaluation are presented in Section~\ref{sec:mobilenetv2}.

\textbf{Stage 4: Result Aggregation} - Since a single frame contains multiple leaves, predictions should be aggregated using weighted combination of detection confidence, classification entropy, and spatial quality metrics. The aggregated result is encoded into LoRaWAN payload. The aggregation strategy and its design rationale are detailed in Section~\ref{subsec:aggregation_strategies}.



\section{Dataset Preparation and Preprocessing}
\label{sec:dataset}
\vspace{-1mm}
Two distinct datasets were used to train the leaf localization and disease classification models. The disease classification trained on dataset that contains single-leaf images on uniform backgrounds, enabling the model to learn disease-specific visual features without background interference. In contrast, the leaf localization trained on dataset that contains natural scenes of grapevine with annotated leaf bounding boxes, reflecting real deployment conditions characterized by occlusions, illumination variability, and background complexity.

In a real-world monitoring scenario, input images captured by camera contains multiple leaves in single frame with complex backgrounds and other environmental factors. So, during inference, localization model first detects leaf regions from full frame vineyard images. Then, the disease classification model diagnoses the disease symptoms on the extracted leaf. This task separation allows each model to specialize in its respective tasks while maintaining robustness under real-world field conditions.

\subsection{The Grape-Leaf Disease Dataset}

The dataset uses a stratified partitioning with fixed 80/20 train-test split, allocating 3,248 images for model training and 814 images for final model testing. The training set is further subdivided into 85\% training (2,761 images) and 15\% validation (487 images). This split enables hyperparameter tuning on the validation set while preserving an independent test set for unbiased performance assessment at the end. Stratified sampling maintains class level proportion across all partitions, preventing from training bias toward majority classes.

\subsubsection*{Preprocessing Techniques}
The input size for the classification model is set to $128 \times 128$ pixels, balancing model capacity with the memory constraints of the ESP32-S3 platform. The original images in the dataset are $256 \times 256$ pixels. To train the model, images are resized to $144 \times 144$ pixels and then randomly cropped to $128 \times 128$ pixels. But in validation and testing, it crops the center region of the resized image instead of random cropping. This allows the model to learn to focus on the most relevant leaf features while discarding edge pixels that may contain noise or artifacts. The random cropping during training also exposes the model to varied spatial contexts improving generalization.

All images are normalized using standard ImageNet preprocessing statistics (mean $\mu = [0.485, 0.456, 0.406]$ and standard deviation $\sigma = [0.229, 0.224, 0.225]$) as common practice in transfer learning with ImageNet pretrained models. Pixel intensities are first scaled to $[0, 1]$ by dividing by 255, then standardized via $x_{\text{norm}} = (x - \mu) / \sigma$. This normalization aligns input distributions with the pretrained MobileNetV2 network, facilitating effective transfer learning and fine-tuning convergence.

\subsubsection*{Training Dataset Augmentation}
Data augmentation applied stochastically on-the-fly during each training epoch using PyTorch's \texttt{torchvision.transforms}, ensuring no two identical augmented samples are generated across epochs. This helps to prevent overfitting when dataset is not large enough to generalize well on unseen data. The augmentation pipeline of training set includes geometric and photometric transformations. Geometric augmentation include random horizontal and vertical flips, rotations, perspective distortions, and occlusions. Photometric augmentation include color jittering, grayscale conversion, and Gaussian blurring. These transformations are applied to simulate real leaf appearance cause by different lighting conditions, camera angles, and environmental backgrounds.

These augmentations applied with specific probabilities and ranges to balance the training dataset diversity while mimicking realistic leaf appearance. However, no augmentation is applied to validation and test sets. This ensures that model performance is evaluated on the original input data.





\subsection{Grapevine Dataset for Leaf Localization}

The leaf localization dataset comprises 531 natural vineyard photographs with manually annotated bounding boxes, enabling training of region-of-interest (ROI) detection models for unconstrained deployment scenarios. Unlike the classification dataset that controlled laboratory conditions, these images capture real-world vineyard complexity. Images with variable leaf densities, overlapping foliage, occluded leaves, diverse lighting conditions, and cluttered backgrounds. The images are sourced from the Grape/Grapes dataset on Kaggle~\cite{kaggle_grape_images_2023}, curated by Nicolaas Regnier.

\subsubsection*{Preprocessing Techniques}
On this dataset preprocessing stage annotation, conversion to YOLO format, input resizing, and intensity normalization are applied. Image annotations were done manually with the assistance of the Segment Anything Model in the Roboflow platform. Each visible leaf instance in the vineyard images was centered with a bounding box and labeled as a single class (leaf). The bounding box coordinates were normalized to the YOLO format, which specifies each box via its center position $(x_c, y_c)$, width $w$, and height $h$, all scaled to the range $[0, 1]$ relative to the image dimensions. This normalization allows the model to learn scale-invariant representations of leaf regions, facilitating training across variable input sizes and resolutions. The complete annotated dataset, titled ``Grape Leaf ROI Detection'', is now publicly available on the Roboflow platform~\cite{roboflow_grape_leaf_2026} and partitioned into training (328 images, 64\%), validation (82 images, 16\%), and test (103 images, 20\%) sets. The partitioning maintains natural distributions of leaf counts and scene complexity across splits, ensuring that the model is trained and evaluated on representative samples of real-world vineyard conditions. Figure~\ref{fig:leaf_localization_sample} illustrates a sample annotated image from the dataset, showcasing bounding boxes around individual grape leaves in a complex vineyard scene. 


The annotated dataset resizes input images to $416 \times 320$ pixels (width $\times$ height) for training the detection model. To fit the model's input requirements while preserving aspect ratios, rectangular training (\texttt{rect=True}) is employed. This approach resizes images via letterboxing, scaling them to fit within the target dimensions while maintaining their original aspect ratio. The remaining space is filled with black padding, preventing distortion artifacts that would otherwise degrade detection accuracy on elongated or irregularly shaped leaves. This preprocessing strategy minimizes computational overhead on the ESP32-S3 device by avoiding complex resizing operations during inference, allowing the model to operate directly on the camera's native output resolution.


For intensity normalization, YOLOv11 utilizes a linear scaling strategy where raw pixel intensities are mapped to the range $[0, 1]$ by dividing by the maximum 8-bit value: $x_{\text{norm}} = x_{\text{raw}}/255$. Unlike many deep learning architectures that require specific ImageNet-derived mean and standard deviation shifts, YOLO's approach minimizes preprocessing overhead while remaining strictly consistent with its pre-training regime. This alignment ensures the preservation of learned features to transfer learning for specialized tasks, such as leaf detection.

Unlike classification, where aggressive color perturbation improves disease recognition, detection training prioritizes geometric robustness and leaf structure preservation. Photometric augmentations operate in the HSV color space. Hue variation is intentionally minimal ($\pm$0.015) to preserve the characteristic green coloration that distinguishes foliage from background, while moderate saturation and brightness perturbations ($\pm$0.4) account for natural lighting variability in vineyard environments.

Geometric augmentations simulate realistic camera positioning scenarios: rotation and shear approximate mounting angle deviations, translation models slight positional shifts, and scale variation covers camera-to-plant distance changes. Both vertical and horizontal flips are applied with 50\% probability. Perspective distortion is kept negligible (0.0001) to avoid unrealistic warping.

The advanced compositing techniques are YOLO-specific augmentations designed for multi-scale robustness. Mosaic augmentation combines four training images into a single grid, improving small-leaf detection and multi-scale feature learning. MixUp probability is intentionally reduced to 5\% (versus a typical 15\%) because excessive pixel-wise blending degrades bounding box localization precision. CopyPaste augments effective dataset size by transferring leaf instances between images, improving occlusion handling. Mosaic is disabled after epoch 50 (\texttt{close\_mosaic=50}) out of 1000 total epochs, allowing the remaining 950 epochs to fine-tune on unmodified images that more closely approximate real inference conditions.

Validation and test sets receive no augmentation, undergoing only letterboxing and normalization to ensure that performance metrics reflect true model capability on canonical inputs.

\section{Leaf Localization ESPDet-Pico Model (YOLO-based)}
\label{sec:espdet_pico}


The first stage of the inference pipeline requires accurate localization and extraction of individual grape leaf regions from unconstrained vineyard imagery. This preprocessing step enables subsequent disease classification by isolating leaves from complex backgrounds, overlapping vegetation, and varying illumination conditions. Given the computational constraints of ESP32-S3 microcontrollers, the leaf localization model must satisfy two competing requirements: sufficient detection accuracy to reliably identify leaf boundaries, and minimal model complexity to enable real-time inference on resource-constrained hardware.

\subsection{Object Detection Framework Selection}

Modern object detection architectures can be broadly categorized into two paradigms: anchor-based two-stage detectors (e.g., Faster R-CNN~\cite{ren2015faster}) and single-stage detectors (e.g., YOLO~\cite{redmon2016you}, SSD~\cite{liu2016ssd}). Two-stage detectors achieve high accuracy through region proposal networks followed by refinement stages, but incur substantial computational overhead unsuitable for embedded deployment. Single-stage detectors directly predict class probabilities and bounding box coordinates in a single forward pass, offering superior inference speed at moderate accuracy cost—an advantageous trade-off for edge AI applications.

The YOLO (You Only Look Once) family~\cite{yolo11_ultralytics} represents the state of the art in efficient single-stage detection. YOLO11n, the nano-scale variant developed by Ultralytics~\cite{yolo11_ultralytics}, serves as the baseline model for this work. YOLO11n employs an anchor-free detection paradigm, eliminating the need for predefined anchor boxes and simplifying post-processing. The architecture comprises a feature extraction backbone with cross-stage partial connections, a feature pyramid network (FPN)~\cite{lin2017feature} for multi-scale fusion, and detection heads operating at three spatial resolutions to capture objects across varying scales.

YOLO11n achieves strong detection performance with 2.59 million parameters and a model size of 5.23~MB. However, these resource requirements exceed the 8~MB PSRAM capacity of the ESP32-S3 platform when accounting for activation memory, input buffers, and runtime overhead. Direct deployment of YOLO11n would necessitate model streaming from external flash storage, introducing prohibitive latency that precludes real-time operation. Consequently, aggressive model compression strategies are required to reduce memory footprint while preserving detection accuracy.

\subsection{YOLO11-Optimization for Resources Constrained Deployment}

To enable ESP32-S3 deployment, we adopt ESPDet-Pico, an ESP-optimized object detector derived from the YOLO11 architecture. ESPDet-Pico applies systematic architectural pruning, replacing computationally expensive operations with hardware-friendly alternatives while maintaining the core detection pipeline.

\subsubsection{Backbone Architecture Modifications}

The feature extraction backbone comprises 11 layers organized into four downsampling stages, achieving spatial resolutions of P3/8, P4/16, and P5/32 relative to the input image. Key architectural modifications include:

\textbf{Depthwise Separable Convolutions (DSConv):} Standard convolutions are replaced with depthwise separable convolutions~\cite{howard2017mobilenets}, factorizing spatial and channel-wise operations into a depthwise $k \times k$ filter followed by a pointwise $1 \times 1$ projection. This reduces computational complexity from $O(C_{in} \times C_{out} \times k^2)$ to $O(C_{in} \times k^2 + C_{in} \times C_{out})$, where $k$ denotes kernel size. For typical layer configurations, this achieves $8$--$9\times$ FLOPs reduction with minimal accuracy degradation.

\textbf{ESP Blocks:} ESPBlockLite and DSC3k2 modules employ hierarchical feature learning through parallel convolutional branches with varying dilation rates. Each branch captures multi-scale contextual information, which is subsequently fused via element-wise addition. Unlike standard residual blocks, ESP blocks maintain constant channel dimensions throughout the module, reducing memory bandwidth requirements.

\textbf{Spatial-Channel Downsampling (SCDown):} Stride-2 downsampling operations combine spatial pooling with channel projection in a single fused operation, reducing intermediate activation storage compared to sequential pooling-and-projection layers employed in YOLO11n.

\textbf{Spatial Pyramid Pooling Fast (SPPF):} The SPPF module, derived from the spatial pyramid pooling concept~\cite{he2015spatial} and optimized in the Ultralytics framework~\cite{yolo11_ultralytics}, applies sequential $5 \times 5$ max pooling operations to capture multi-scale features efficiently. Compared to parallel pooling branches in the original SPP design, SPPF reduces memory allocation overhead by reusing intermediate pooled features.

\subsubsection{Detection Head Architecture}

The detection head comprises two functional components: a \textit{neck} that fuses multi-scale backbone features, and a \textit{prediction module} that produces per-scale bounding box and classification outputs.

\paragraph{Feature Pyramid Neck.}
The neck follows a bidirectional Feature Pyramid Network (FPN) design~\cite{lin2017feature}, fusing features from backbone stages P3 (1/8 scale), P4 (1/16 scale), and P5 (1/32 scale) to enable multi-scale detection. Feature fusion proceeds through three pathways:

\begin{enumerate}
    \item \textbf{Top-down pathway:} P5 features are upsampled by $2\times$ via nearest-neighbor interpolation and concatenated channel-wise with P4 backbone features. The concatenated tensor is processed by two sequential ESPBlock layers (each containing a DSBottleneck with residual connection), producing fused features at 1/16 scale.
    \item \textbf{Second top-down stage:} The fused 1/16 features are upsampled by $2\times$ and concatenated with P3 backbone features, then processed by two ESPBlock layers to produce the small-object detection features at 1/8 scale.
    \item \textbf{Bottom-up pathway:} A DSConv with stride 2 downsamples the 1/8 features and concatenates them with the 1/16 fused features from step~1, processed by two ESPBlock layers to produce medium-object features. A second stride-2 DSConv downsamples these and concatenates with the backbone layer~10 output, followed by two ESPBlock layers to produce large-object features at 1/32 scale.
\end{enumerate}

This bidirectional design ensures that each detection scale benefits from both fine-grained spatial detail (via top-down flow from higher-resolution stages) and strong semantic context (via bottom-up flow from deeper stages).

\paragraph{Decoupled Prediction Heads.}
At each of the three detection scales, two parallel prediction branches produce separate outputs for bounding box regression and object classification. This decoupled head design, inherited from YOLO11, separates localization and classification into independent sub-networks, avoiding the task conflict that arises when a single shared branch must simultaneously optimize for both objectives.

The \textit{box regression branch} (denoted \texttt{cv2}) at each scale consists of two consecutive DSConv layers followed by a $1 \times 1$ convolution that outputs 4 channels. Each channel corresponds to one edge distance $(l, t, r, b)$, representing the distances from the grid cell center to the left, top, right, and bottom edges of the predicted bounding box, respectively. This distance-based parameterization differs from the conventional center-size encoding $(x, y, w, h)$ used in earlier YOLO versions and eliminates the need for anchor box priors, as bounding boxes are directly regressed from each spatial grid position in an anchor-free manner.

The \textit{classification branch} (denoted \texttt{cv3}) at each scale comprises two sequential blocks of depthwise convolution (DWConv) followed by a $1 \times 1$ pointwise convolution, terminated by a $1 \times 1$ convolution that outputs $n_c$ channels (where $n_c = 1$ for the single leaf class). The output represents the class logit score for each grid cell.

\paragraph{Simplified Box Regression (\texttt{reg\_max}$=1$).}
A key distinction from standard YOLO11 lies in the box regression formulation. In the standard YOLO11 detection head, each edge distance is predicted as a discrete probability distribution over 16 bins (\texttt{reg\_max}$=16$), followed by a Distribution Focal Loss (DFL)~\cite{li2020generalized} layer that computes the expected value via softmax-weighted summation. This distribution-based regression enables the model to express localization uncertainty and improves accuracy on objects with ambiguous boundaries.

ESPDetect reduces \texttt{reg\_max} from 16 to 1, replacing the 16-bin distributional regression with direct scalar prediction for each edge distance. This modification has three consequences:
\begin{itemize}
    \item \textbf{Output reduction:} The box regression branch outputs 4 channels per spatial location instead of $4 \times 16 = 64$, reducing the prediction tensor size by $16\times$.
    \item \textbf{DFL elimination:} Since \texttt{reg\_max}$=1$, the DFL layer degenerates to an identity operation and is bypassed entirely, removing the softmax computation from the inference path.
    \item \textbf{Per-anchor output:} The total output per grid cell is $n_c + 4 \times \texttt{reg\_max} = 1 + 4 = 5$ values, compared to $1 + 64 = 65$ in standard YOLO11.
\end{itemize}

This simplification substantially reduces the computational and memory cost of the detection head, which is critical for ESP32-S3 deployment where integer multiply-accumulate operations dominate inference latency.

\paragraph{Multi-Scale ONNX Export Format.}
For deployment on the ESP-DL inference runtime, the model is exported to ONNX format using a custom export path (\texttt{export\_onnx\_forward}) that produces six separate output tensors rather than the single concatenated tensor used in standard YOLO inference. Specifically, the exported model returns:
\begin{equation}
\text{Output} = \{(\mathbf{B}_s, \mathbf{S}_s)\}_{s \in \{P3, P4, P5\}}
\end{equation}
where $\mathbf{B}_s \in \mathbb{R}^{1 \times 4 \times H_s \times W_s}$ contains raw box regression values and $\mathbf{S}_s \in \mathbb{R}^{1 \times 1 \times H_s \times W_s}$ contains raw class logits at scale $s$. Post-processing---including sigmoid activation, distance-to-box coordinate conversion, and non-maximum suppression---is deferred to the ESP-DL runtime on the microcontroller, avoiding the need for complex tensor reshaping and concatenation operations within the exported model graph.

\subsubsection{Parameter and Memory Reduction}

Through systematic architecture pruning, ESPDet-Pico reduces the parameter count from 2.59 million (YOLO11n) to approximately 360,000—an 86\% reduction. Model size decreases from 5.23~MB to 1.06~MB in FP32 precision (79.8\% reduction), enabling the model to fit entirely within ESP32-S3 PSRAM alongside activation buffers. Width scaling factor $w=0.25$ reduces channel dimensions (e.g., base 512 channels become 128), while depth scaling factor $d=0.50$ reduces internal block repetitions (e.g., base 2$\times$ DSC3k2 becomes 1$\times$), jointly preserving the hierarchical feature extraction structure at reduced computational cost.

\subsection{ESPDet-Pico Model Training and Optimization}

With the compressed architecture established, training focuses on optimizing detection accuracy under the reduced model capacity constraint. ESPDet-Pico was trained on the grapevine leaf localization dataset described in Section~\ref{sec:dataset}, comprising 328 training images, 82 validation images, and 103 test images. All images contain annotated bounding boxes for individual grape leaf instances in unconstrained vineyard scenes.

\subsubsection{Input Resolution and Rectangular Training}

The model accepts input images at $416 \times 320$ pixel resolution (width $\times$ height). Rectangular training (\texttt{rect=True}) is employed, where images within each batch are resized to maintain their original aspect ratio through letterboxing with black padding. This strategy reduces computational waste on padding pixels compared to square resizing and better preserves object proportions, particularly beneficial for elongated leaves in vineyard imagery.

\subsubsection{Optimization Configuration}

Training employed the AdamW optimizer~\cite{loshchilov2017decoupled} with weight decay regularization to prevent overfitting on the moderate-sized dataset. Key hyperparameters include:

\begin{itemize}
    \item \textbf{Learning rate:} Initial learning rate $\eta_0 = 0.002$ with cosine annealing schedule~\cite{loshchilov2016sgdr} decaying to final learning rate $\eta_f = 0.00002$ (ratio $\eta_f / \eta_0 = 0.01$). Cosine annealing provides smooth learning rate decay without manual tuning of decay milestones.
    \item \textbf{Warmup strategy:} The first 3 epochs employ linear learning rate warmup from $\eta_{warmup} = 0.0001$ to the initial learning rate $\eta_0$, stabilizing early training dynamics.
    \item \textbf{Momentum and weight decay:} Momentum coefficient $\beta_1 = 0.937$, weight decay $\lambda = 0.0005$.
    \item \textbf{Batch size:} 32 samples per batch, balancing training stability with GPU memory utilization.
    \item \textbf{Training duration:} Maximum 1000 epochs with early stopping patience set to 75 epochs, terminating training if validation mAP@50 does not improve for 75 consecutive epochs.
\end{itemize}

Mixed precision training (AMP) was enabled to accelerate training on GPUs with tensor cores, reducing memory footprint and training time without sacrificing numerical stability.

\subsubsection{Loss Function}

The training objective combines three loss components:
\begin{equation}
\mathcal{L}_{\text{total}} = \lambda_{\text{box}} \mathcal{L}_{\text{box}} + \lambda_{\text{cls}} \mathcal{L}_{\text{cls}} + \lambda_{\text{dfl}} \mathcal{L}_{\text{dfl}}
\end{equation}
where $\mathcal{L}_{\text{box}}$ denotes the Complete IoU (CIoU) loss~\cite{zheng2020distance} for bounding box regression, $\mathcal{L}_{\text{cls}}$ represents the binary cross-entropy loss for objectness classification, and $\mathcal{L}_{\text{dfl}}$ is the distribution focal loss for box coordinate refinement. 

To prioritize localization accuracy over classification confidence in this single-class detection task (leaf versus background), the loss components are reweighted: $\lambda_{\text{box}} = 7.5$ (elevated for precise bounding box regression), $\lambda_{\text{cls}} = 0.5$ (reduced, as the model only distinguishes leaves from background), and $\lambda_{\text{dfl}} = 1.5$ (standard weight for anchor-free detection). The elevated box loss weight emphasizes precise localization accuracy, critical for subsequent cropping operations in the inference pipeline.

\subsubsection{Data Augmentation Strategy}

The data augmentation pipeline for detection training is designed to enhance model robustness to the variability of real vineyard conditions while preserving the integrity of bounding box annotations. \section{Disease Classification Model (MobileNetV2)}
\label{sec:mobilenetv2}

Following the leaf localization, each detected leaf region undergoes disease classification to diagnose if the leaf is affected by pathology. This stage requires high classification accuracy to ensure reliable disease diagnosis while maintaining computational efficiency for embedded deployment. The classification model must generalize well across grape disease categories despite the moderate training dataset size, while fitting within the constrained memory allocation and power consumption requirements. Hence, a lightweight convolutional neural network architecture with proven transfer learning capabilities is selected as the backbone for disease classification. 



\subsection{Convolutional Neural Network Architecture}

The disease classification model is based on MobileNetV2~\cite{sandler2018mobilenetv2}, a lightweight convolutional neural network architecture specifically designed for resource-constrained mobile and embedded devices. MobileNetV2 achieves computational efficiency due to its architectural design. It is designed with a focus on reducing the number of parameters and floating-point operations (FLOPs). The key architectural design elements that enable MobileNetV2's efficiency are the use of depthwise separable convolutions and the introduction of inverted residual blocks with linear bottlenecks.

\subsubsection*{Depthwise Separable Convolutions}

Standard convolutional layers perform joint spatial and channelwise filtering, obtaining computational cost proportional to $C_{in} \times C_{out} \times k^2 \times H \times W$, where $C_{in}$ and $C_{out}$ denote input and output channels, $k$ is the kernel size, and $H \times W$ represents the spatial dimensions. MobileNetV2 factorizes this operation into two sequential steps in the following manner:

\begin{enumerate}
    \item \textbf{Depthwise convolution:} Applies a single $k \times k$ filter independently to each input channel, producing $C_{in}$ feature maps. Computational cost reduces to $C_{in} \times k^2 \times H \times W$.
    \item \textbf{Pointwise convolution:} Projects the depthwise features into $C_{out}$ output channels using $1 \times 1$ convolutions, costing $C_{in} \times C_{out} \times H \times W$.
\end{enumerate}

The total computational cost becomes $(C_{in} \times k^2 + C_{in} \times C_{out}) \times H \times W$. For typical configurations where $C_{out} \gg k^2$, this factorization achieves a lot of FLOPs reduction compared to standard convolutions. Depthwise separable convolutions significantly reduce the number of parameters and computational cost while maintaining representational capacity, making them ideal for mobile and embedded applications. However, they may introduce a slight accuracy drop compared to standard convolutions, which is mitigated through careful architectural design and training strategies.

\subsubsection*{Inverted Residual Blocks}

Traditional residual blocks~\cite{he2016deep} employ wide-narrow-wide channel configurations, where intermediate layers have fewer channels than input/output layers to reduce computation. MobileNetV2 inverts this design, using narrow-wide-narrow blocks that expand the channel dimension in intermediate layers through $1 \times 1$ convolutions, apply depthwise convolution in the high-dimensional space, and then project back to a narrow output via $1 \times 1$ linear projection without activation (linear bottleneck). This architecture enables efficient feature transformation while maintaining low-dimensional bottleneck representations suitable for memory-constrained devices.

Skip connections are applied only when input and output dimensions match, allowing gradient flow and facilitating training convergence. The linear bottlenecks prevent information loss from ReLU activation~\cite{sandler2018mobilenetv2}, which would otherwise zero-out negative values in low-dimensional spaces. The combination of depthwise separable convolutions and inverted residual blocks allows MobileNetV2 to achieve a favorable accuracy-efficiency trade-off, making it a strong candidate for the disease classification task in this project.

\subsubsection*{Model Configuration and Pre-training}

The MobileNetV2 backbone is initialized with weights pre-trained on ImageNet~\cite{deng2009imagenet},a massive visual database containing over 14 million high-resolution images across 1000 object categories. Pre-training provides generic low-level and mid-level visual features transferable to the grape disease classification domain, accelerating convergence and improving generalization compared to random initialization.

The input resolution is set to $128 \times 128$ pixels, to fit within the memory capacity constraint. The orginal input image size was $256 \times 256$ pixels, but it was reduced to $128 \times 128$ to reduce the computational load and memory footprint of the model. However, the controlled nature of the PlantVillage dataset enables effective disease recognition at reduced resolution. The reduced input size also decreases memory footprint for runtime activations during inference. 

The classification head consists of a global average pooling layer that aggregates the $4 \times 4 \times 1280$ feature maps (resulting from the $128 \times 128$ input resolution downsampled by a stride factor of 32 through the network) into a 1280 dimensional feature vector, followed by a dropout layer (dropout rate $p=0.5$) for regularization, and a final fully connected layer with 4 output units (one per disease class). The dropout layer prevents overfitting by randomly deactivating 50\% of neurons during training, forcing the network to learn robust distributed representations rather than over memorizing. The complete forward pass through the adapted MobileNetV2 architecture is summarized as:

\begin{equation}
128 \times 128 \times 3 \xrightarrow{\text{backbone}} 4 \times 4 \times 320 \xrightarrow{1\times1 \text{ conv}} 4 \times 4 \times 1280 \xrightarrow{\text{GAP}} 1280 \xrightarrow{\text{FC}} 4
\label{eq:mobilenet_forward}
\end{equation}

\subsection{Transfer Learning Strategy}

Adapting ImageNet pre-trained weights to the grape disease classification domain requires careful fine-tuning to leverage generic visual features while learning grape leaf disease specific patterns. A two-stage progressive fine-tuning strategy is employed to balance feature transfer (Transfer Learning) with domain specific specialization (Fine-tuning).

\subsubsection{Stage 1: Classifier Head Training}

The first stage focuses on training the randomly initialized classification head while keeping the pre-trained MobileNetV2 backbone frozen. This gives stable and informative features to the classifier head. By freezing the backbone, the classifier head can rapidly adapt to the specific disease categories. This is  a fine-tuning with high learning rates on a small domain-specific dataset destroys useful pre-trained representations~\cite{yosinski2014transferable}. During this stage, only the global average pooling, dropout, and fully connected layers receive gradient updates.

In a few epochs with initial learning rate $\eta_1 = 10^{-3}$. The relatively high learning rate enables rapid adaptation of the classification head to the four grape disease categories. Few epochs are sufficient for the classifier head to learn, while preventing overfitting. The frozen backbone ensures that the generic visual features learned from ImageNet are preserved, providing a strong foundation for subsequent fine-tuning.

\subsubsection{Stage 2: Full Model Fine-tuning}

The second stage unfreezes all layers and fine-tunes the entire network. This stage allows the backbone to adapt its training dataset features. It refines the learned feature according to the specific visual characteristics of grape diseases leaf patterns.

Unlike the first stage, fine-tuning requires much more epochs with reduced learning rate $\eta_2 = 10^{-4}$. The 10$\times$ learning rate. The reduction compared to Stage 1 ensures stable fine-tuning of pre-trained weights without destabilizing learned representations. The sufficient number of epochs provides sufficient iterations for convergence while preventing overfitting, as validated through early stopping on the validation set.


\subsection{MobileNetV2 Training and Optimization Techniques}

\subsubsection*{Optimization and other Hyperparameters Configuration}

Both training stages employ the AdamW optimizer~\cite{loshchilov2017decoupled}, which combines adaptive learning rates with decoupled weight decay regularization. AdamW decouples the weight decay term from the gradient-based update, applying L2 regularization directly to weights rather than through gradient computation. This modification improves generalization compared to standard Adam~\cite{kingma2014adam} by preventing weight decay from interfering with adaptive learning rate scaling.
Hyperparameters are configured to balance convergence speed with generalization performance.The learning rate is set to $\eta_1 = 10^{-3}$ for Stage~1 and reduced to $\eta_2 = 10^{-4}$ for Stage~2, enabling coarse adaptation of the classifier head before fine-grained tuning of the full network. Weight decay is configured at $\lambda = 10^{-4}$ as the L2 regularization coefficient, and the momentum parameters retain the AdamW defaults ($\beta_1 = 0.9$, $\beta_2 = 0.999$). A batch size of 32 samples is used throughout both stages, balancing training stability with GPU memory utilization.

\subsubsection*{Loss Function}

Training minimizes the cross-entropy loss for multi-class classification:
\begin{equation}
\mathcal{L}_{\text{CE}} = -\frac{1}{N} \sum_{i=1}^{N} \sum_{c=1}^{C} y_{ic} \log(\hat{y}_{ic})
\end{equation}
where $N$ denotes batch size, $C=4$ is the number of disease classes, $y_{ic} \in \{0,1\}$ represents the ground truth label (one-hot encoded), and $\hat{y}_{ic} = \text{softmax}(z_c)$ is the predicted probability for class $c$ of sample $i$. Cross-entropy loss penalizes confident incorrect predictions more heavily than near-boundary errors, encouraging the model to learn discriminative class boundaries. The main purpose of loss function is to optimize model parameters during evaluation. 

\subsubsection*{On-the-fly Data Augmentation}

Beyond weight decay and dropout, the data augmentation pipeline described in Section~\ref{sec:dataset} provides implicit regularization by presenting diverse augmented variations of each training sample. The combination of geometric transformations (rotation, scaling, translation) and photometric perturbations (color jitter, brightness adjustment) exposes the model to realistic deployment variability, improving robustness to lighting changes, leaf orientation variations, and camera perspective differences encountered in vineyard environments.
\subsubsection*{Early Stopping and Model Checkpointing}
Early stopping monitors validation loss with patience set to 10 epochs. Training terminates if validation loss does not improve for 10 consecutive epochs, preventing overfitting beyond the optimal checkpoint. The model snapshot with lowest validation loss across all epochs is retained as the final model.

\subsubsection*{Multi-Seed Experimentals}

To assess model stability and generalization consistency, training is repeated with four different random seeds: 42, 123, 456, and 789. Each seed initializes the random number generator controlling parameter initialization, data shuffling, and stochastic augmentation. This protocol quantifies performance variance attributable to random initialization rather than systematic dataset characteristics, providing confidence intervals for reported accuracy metrics~\cite{henderson2018deep}.

To enable deployment on the ESP32-S3 microcontroller, the trained FP32 MobileNetV2 model must undergo post-training quantization (PTQ) to convert floating-point weights and activations to 8-bit integers. The detailed quantization pipeline, including calibration procedures, equalization strategies, and the ESP-PPQ framework configuration, is presented in Section~\ref{sec:quantization_pipeline} of Chapter~\ref{chap:deployment}.

\subsubsection{Accuracy-Efficiency Trade-off Analysis}

ResNet18 achieves perfect test accuracy (100.00\%, 814/814 correct), while MobileNetV2 misclassifies one Black~Rot sample as Esca (99.88\% accuracy). Despite this marginal accuracy difference ($\Delta = 0.12$ percentage points), MobileNetV2 demonstrates a fundamentally superior accuracy-efficiency trade-off for resource-constrained deployment:

\begin{itemize}
    \item \textbf{Computational efficiency:} MobileNetV2 requires 6$\times$ fewer FLOPs (300M vs 1.8B) due to depthwise separable convolutions, which factorize standard convolutions into depthwise and pointwise operations. This reduction directly translates to lower inference latency on the ESP32-S3's 240~MHz Xtensa LX7 cores.
    \item \textbf{Memory efficiency:} MobileNetV2's 8.48~MB FP32 model compresses to 2.27~MB INT8 (Section~\ref{sec:quantization_pipeline}), fitting comfortably within the 8~MB PSRAM alongside the ESPDet-Pico detection model (478~KB INT8) and activation buffers ($\sim$3~MB). ResNet18's 44.7~MB FP32 model would exceed the available memory budget even after quantization (estimated 11.2~MB INT8), precluding dual-model deployment.
    \item \textbf{Quantization robustness:} MobileNetV2's batch normalization and inverted residual structure exhibit inherent robustness to INT8 quantization, maintaining $>99.5\%$ accuracy post-quantization (Section~\ref{subsec:quantization_accuracy}). ResNet18's deeper standard convolutions typically show greater quantization sensitivity, particularly in the initial and final layers.
\end{itemize}

\subsubsection{Statistical Significance of Accuracy Difference}

The 0.12 percentage point accuracy difference (1 additional error in 814 samples) is not statistically significant for agricultural disease monitoring applications. A binomial proportion test comparing $p_{\text{MobileNet}} = 0.9988$ versus $p_{\text{ResNet}} = 1.0000$ yields $p > 0.3$, indicating insufficient evidence to conclude that ResNet18 generalizes better than MobileNetV2 on unseen data. The single MobileNetV2 misclassification involves the visually ambiguous Black~Rot--Esca boundary, where both diseases manifest necrotic lesions and leaf discoloration. In operational vineyard monitoring, such edge-case errors (0.12\% frequency) have negligible impact compared to environmental confounds (lighting variation, occlusion, motion blur) that affect both models equally.

\subsubsection{Architectural Implications for Edge Deployment}

The fundamental architectural distinction—depthwise separable convolutions versus standard convolutions—determines deployability on microcontroller-class hardware. Standard $3\times3$ convolutions in ResNet18 apply $C_{\text{in}} \times C_{\text{out}} \times 9$ multiply-accumulate operations per spatial location, while MobileNetV2's depthwise separable convolutions reduce this to $(C_{\text{in}} \times 9) + (C_{\text{in}} \times C_{\text{out}} \times 1)$ operations via factorization. For typical layer dimensions ($C_{\text{in}} = C_{\text{out}} = 128$), this yields an 8--9$\times$ reduction in computation per layer.

This efficiency gain compounds across the 17 inverted residual blocks, enabling real-time inference ($\sim$6.4~seconds for 10 leaves, Chapter~\ref{chap:performance_evaluation}) on the ESP32-S3 without specialized accelerators. ResNet18's 6$\times$ higher FLOP count would proportionally increase latency to $\sim$38~seconds per frame, violating the responsiveness requirements for interactive vineyard monitoring.

\subsubsection{Model Selection Rationale}

MobileNetV2 is selected as the disease classification backbone for the following reasons:

\begin{enumerate}
    \item \textbf{Memory constraint compliance:} The quantized model (2.27~MB) fits within the available PSRAM budget, enabling concurrent deployment with ESPDet-Pico for the complete two-stage pipeline.
    \item \textbf{Negligible accuracy cost:} The 0.12\% accuracy reduction relative to ResNet18 is statistically insignificant and operationally irrelevant for the target application.
    \item \textbf{Inference efficiency:} 6$\times$ lower computational cost reduces per-frame latency and power consumption, critical for battery-operated sensor nodes.
    \item \textbf{Quantization-friendly architecture:} Batch normalization and inverted residuals maintain high accuracy under aggressive INT8 quantization, whereas ResNet18's quantization robustness remains unverified.
\end{enumerate}

These results validate the hypothesis that MobileNetV2's mobile-optimized design provides the optimal balance between classification accuracy and deployment feasibility for ESP32-S3 microcontroller platforms, achieving task-sufficient accuracy (99.88\%) within stringent hardware constraints that preclude larger alternatives.
