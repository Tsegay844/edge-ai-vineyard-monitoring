\chapter{{Edge AI System Design \& Implementation}}

\section{System Overview and Methodology}

This chapter presents the design, implementation, and deployment of an edge AI-based grape leaf disease detection system into existing vineyard monitoring infrastructure. The proposed system extends conventional LoRaWAN-based wireless sensor networks, which monitor only environmental parameters, by integrating sensor-level deep learning inference to enable real-time plant health status assessment.



\subsection{Four-Stage Pipeline Architecture}

The disease detection system is implemented in a four-stage pipeline deployed on ESP32-S3 microcontrollers, as illustrated in Figure~\ref{fig:system_architecture}.

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.75\linewidth]{images/system_architecture.png}

    \caption{Four-stage edge AI pipeline for grape leaf disease detection.}
    \label{fig:system_architecture}
\end{figure}

\textbf{Stage 1: Image Acquisition} -- An OV3660 camera module captures vineyard images at VGA resolution. The camera's built-in hardware JPEG encoder compresses images on-chip before transfer to the ESP32-S3.

\textbf{Stage 2: Leaf Localization} -- A YOLO-based detection model (ESPDet-Pico) localizes individual grape leaves within the captured frame. This stage identifies and crops leaf regions of interest, filtering out background elements. The ESP-optimized model architecture and training procedure are detailed in Section~\ref{sec:espdet_pico}.

\textbf{Stage 3: Disease Classification} -- Each detected leaf is resized and classified by a MobileNetV2 model fine-tuned on grape disease images. The two-stage transfer learning strategy and model evaluation are presented in Section~\ref{sec:mobilenetv2}.

\textbf{Stage 4: Multi-Leaf Aggregation} -- Since frames contain multiple leaves, predictions are aggregated using weighted combination of detection confidence, classification entropy, and spatial quality metrics. The aggregated result is encoded into a 16-byte LoRaWAN packet. The aggregation strategy and its effectiveness are analyzed in Chapter~\ref{chap:results}.



\section{Dataset and Preprocessing Techniques}
\label{sec:dataset}
\vspace{-1mm}
Two distinct datasets were employed to train the leaf localization and disease classification models. The disease classification dataset comprises single-leaf images on uniform backgrounds, enabling the model to learn disease-specific visual features without background interference. In contrast, the leaf localization dataset contains natural vineyard scenes with annotated leaf bounding boxes, reflecting real deployment conditions with complex backgrounds, occlusions, and varying illumination. During inference, the localization model first detects leaf regions in unconstrained imagery, and the classification model subsequently processes the extracted leaf crops. This separation allows each model to specialize in its respective task while ensuring robust performance on real-world vineyard imagery.
\vspace{-2mm}
\subsection{The Grape-Leaf Disease Dataset}
\vspace{-2mm}
The grape-leaf disease dataset was obtained from the PlantVillage Dataset hosted on Kaggle~\cite{plantvillage_dataset_2023}, created by Abdallah Ali. PlantVillage is a widely-adopted public repository of plant disease imagery developed through collaborative citizen science efforts. The grape leaf subset aggregates pathology images captured under controlled laboratory conditions, ensuring consistent lighting and background characteristics. The dataset emphasizes leaf-level disease manifestations across four epidemiologically significant categories affecting viticulture worldwide. The dataset contains 4,062 RGB images distributed across four distinct disease classes: \textit{Black Rot} (caused by \textit{Guignardia bidwellii}), \textit{Esca} (Black Measles, a complex disease involving multiple fungal pathogens), \textit{Leaf Blight} (Isariopsis Leaf Spot, caused by \textit{Pseudocercospora vitis}), and \textit{Healthy} (disease-free grape leaf samples). This three-way split enables hyperparameter tuning on the validation set while preserving the test set for unbiased performance evaluation. All splits maintain class balance through stratified partitioning to prevent training bias toward majority classes.

\subsection{Grapevine Dataset for Leaf Localization}

The leaf localization dataset is used to train a model to identify grape leaf regions of interest (ROI) within unconstrained vineyard imagery. Unlike the classification dataset's controlled backgrounds, this dataset includes natural vineyard scenes with complex backgrounds, occlusions, and varying lighting conditions. The base images are sourced from the Grape/Grapes dataset on Kaggle~\cite{kaggle_grape_images_2023}, curated by Nicolaas Regnier. This collection contains 531 natural vineyard photographs capturing real-world deployment conditions with varying leaf densities, overlaps, lighting conditions, and background complexity—essential characteristics for training robust leaf localization models that generalize beyond laboratory settings.

To adapt this dataset for object detection training, the images were manually annotated with bounding boxes delimiting individual grape leaf regions. The annotation process was conducted using the Roboflow platform and Segment Anything Model (SAM), where each leaf instance within the images was labeled with precise bounding box coordinates. Annotations follow the YOLO format, where each bounding box is specified by normalized center coordinates $(x_c, y_c)$, width $w$, and height $h$, all scaled to $[0, 1]$ relative to image dimensions. This normalization ensures resolution-independent annotation representation, facilitating training across variable input sizes. The annotated dataset, titled ``Grape Leaf ROI Detection'', is publicly available on the Roboflow platform~\cite{roboflow_grape_leaf_2026}. The dataset was exported in YOLOv11 format compatible with modern object detection frameworks and partitioned into training (328 images), validation (82 images), and test (103 images) sets, maintaining the natural distribution of leaf counts and scene complexity across splits. 


\subsection{Preprocessing and Augmentation Pipeline}

Data preprocessing and augmentation strategies differ substantially between the classification and detection tasks due to their distinct architectural requirements and input constraints.

\subsubsection{Resolution Adaptation for Embedded Constraints}

Hardware memory limitations of the ESP32-S3 platform impose strict constraints on input resolution. The classification model operates on $128 \times 128$ pixel inputs, selected to balance model capacity with PSRAM availability for activation storage. The detection model accepts $640 \times 480$ pixel inputs (VGA resolution), matching the native OV3660 camera output to minimize preprocessing overhead on-device.

For classification training, images are resized to $144 \times 144$ pixels followed by center cropping to $128 \times 128$ during validation and testing. Training images undergo random cropping (discussed below) instead of deterministic center cropping to increase sample diversity. Detection images are resized to $640 \times 480$ using letterboxing: the original aspect ratio is preserved by padding with black pixels to fill the target dimensions.

\subsubsection{Intensity Normalization and Standardization}

All images undergo channel-wise normalization using ImageNet statistics: mean $\mu = [0.485, 0.456, 0.406]$ and standard deviation $\sigma = [0.229, 0.224, 0.225]$ for red, green, and blue channels respectively. This normalization aligns input distributions with the pre-training regime of transfer learning base models (MobileNetV2 for classification, YOLO11n for detection), accelerating convergence during fine-tuning. Pixel intensities are first scaled to $[0, 1]$ by dividing by 255, then standardized via $x_{\text{norm}} = (x - \mu) / \sigma$.

\subsubsection{Geometric and Photometric Augmentation Techniques}

Data augmentation is applied exclusively to the classification training set to improve model generalization and mitigate overfitting given the moderate dataset size. The detection dataset undergoes minimal augmentation during training (handled internally by the YOLO training framework), while the detection test set receives no augmentation.

Classification training augmentation pipeline comprises:

\begin{itemize}
    \item \textbf{RandomResizedCrop}: Crops random portions of the image scaled between 50\% to 100\% of the original size, then resizes to $128 \times 128$. This simulates varying leaf sizes and camera distances.
    
    \item \textbf{RandomHorizontalFlip}: Applies horizontal mirroring with 50\% probability, reflecting the natural symmetry of vineyard scenes.
    
    \item \textbf{RandomVerticalFlip}: Applies vertical mirroring with 20\% probability, addressing arbitrary camera orientations during field deployment.
    
    \item \textbf{RandomRotation}: Rotates images randomly within $\pm 25^\circ$, accommodating non-upright leaf orientations and varied camera mounting angles.
    
    \item \textbf{ColorJitter}: Randomly adjusts brightness, contrast, saturation, and hue within ranges: brightness $\pm 50\%$, contrast $\pm 50\%$, saturation $\pm 50\%$, hue $\pm 15\%$. This augmentation enhances robustness to varying lighting conditions, cloud cover, and time-of-day illumination changes in outdoor deployments.
    
    \item \textbf{RandomPerspective}: Applies random perspective transformations with distortion probability 40\% and distortion scale 0.3, simulating oblique viewing angles.
    
    \item \textbf{RandomGrayscale}: Converts images to grayscale with 15\% probability, encouraging the model to rely on texture and shape features rather than color alone.
    
    \item \textbf{GaussianBlur}: Applies Gaussian kernel blurring (kernel size 3, $\sigma \in [0.1, 1.5]$) to simulate slight camera defocus or motion blur.
    
    \item \textbf{RandomErasing}: Randomly erases rectangular regions (probability 30\%, area 2-15\% of image) to improve occlusion robustness.
\end{itemize}

These transformations are applied stochastically during each training epoch, generating diverse augmented samples without explicit dataset expansion.

\subsubsection{Augmentation-Free Validation Protocol}

Validation and test sets for both classification and detection tasks receive only deterministic preprocessing (resizing, normalization) without stochastic augmentation. This protocol ensures performance metrics reflect true model capability on canonical inputs, avoiding artificially inflated accuracies from test-time augmentation. The separation of augmented training data from clean validation/test data maintains rigorous evaluation standards consistent with machine learning best practices.

\section{Leaf Localization ESPDet-Pico Model (YOLO-based)}
\label{sec:espdet_pico}

The first stage of the inference pipeline requires accurate localization and extraction of individual grape leaf regions from unconstrained vineyard imagery. This preprocessing step enables subsequent disease classification by isolating leaves from complex backgrounds, overlapping vegetation, and varying illumination conditions. Given the computational constraints of ESP32-S3 microcontrollers, the leaf localization model must satisfy two competing requirements: sufficient detection accuracy to reliably identify leaf boundaries, and minimal model complexity to enable real-time inference on resource-constrained hardware.

\subsection{Object Detection Framework Selection}

Modern object detection architectures can be broadly categorized into two paradigms: anchor-based two-stage detectors (e.g., Faster R-CNN~\cite{ren2015faster}) and single-stage detectors (e.g., YOLO~\cite{redmon2016you}, SSD~\cite{liu2016ssd}). Two-stage detectors achieve high accuracy through region proposal networks followed by refinement stages, but incur substantial computational overhead unsuitable for embedded deployment. Single-stage detectors directly predict class probabilities and bounding box coordinates in a single forward pass, offering superior inference speed at moderate accuracy cost—an advantageous trade-off for edge AI applications.

The YOLO (You Only Look Once) family~\cite{redmon2016you,jocher2022ultralytics} represents the state of the art in efficient single-stage detection. YOLO11n, the latest nano-scale variant developed by Ultralytics~\cite{jocher2022ultralytics}, serves as the baseline model for this work. YOLO11n employs an anchor-free detection paradigm, eliminating the need for predefined anchor boxes and simplifying post-processing. The architecture comprises a feature extraction backbone with cross-stage partial connections, a feature pyramid network (FPN)~\cite{lin2017feature} for multi-scale fusion, and detection heads operating at three spatial resolutions to capture objects across varying scales.

YOLO11n achieves strong detection performance with 2.59 million parameters and a model size of 5.23~MB in FP32 precision. However, these resource requirements exceed the 8~MB PSRAM capacity of the ESP32-S3 platform when accounting for activation memory, input buffers, and runtime overhead. Direct deployment of YOLO11n would necessitate model streaming from external flash storage, introducing prohibitive latency (typically exceeding 2 seconds per inference) that precludes real-time operation. Consequently, aggressive model compression strategies are required to reduce memory footprint while preserving detection accuracy.

\subsection{Model Compression for Embedded Deployment}

To enable ESP32-S3 deployment, we adopt ESPDet-Pico~\cite{li2023espdet}, an ESP-optimized object detector derived from the YOLO11 architecture. ESPDet-Pico applies systematic architectural pruning, replacing computationally expensive operations with hardware-friendly alternatives while maintaining the core detection pipeline.

\subsubsection{Backbone Architecture Modifications}

The feature extraction backbone comprises 11 convolutional layers organized into four downsampling stages, achieving spatial resolutions of P3/8, P4/16, and P5/32 relative to the input image. Table~\ref{tab:espdet_backbone} details the complete backbone architecture.

Key architectural modifications include:

\textbf{Depthwise Separable Convolutions (DSConv):} Standard $3 \times 3$ convolutions are replaced with depthwise separable convolutions~\cite{howard2017mobilenets}, factorizing spatial and channel-wise operations. This reduces computational complexity from $O(C_{in} \times C_{out} \times k^2)$ to $O(C_{in} \times k^2 + C_{in} \times C_{out})$, where $k$ denotes kernel size. For typical layer configurations, this achieves $8$--$9\times$ FLOPs reduction with minimal accuracy degradation.

\textbf{ESP Blocks:} ESPBlockLite and DSC3k2 modules~\cite{mehta2018espnetv2} employ hierarchical feature learning through parallel convolutional branches with varying dilation rates. Each branch captures multi-scale contextual information, which is subsequently fused via element-wise addition. Unlike standard residual blocks, ESP blocks maintain constant channel dimensions throughout the module, reducing memory bandwidth requirements.

\textbf{Spatial-Channel Downsampling (SCDown):} Stride-2 downsampling operations combine spatial pooling with channel projection in a single fused operation, reducing intermediate activation storage compared to sequential pooling-and-projection layers employed in YOLO11n.

\textbf{Spatial Pyramid Pooling Fast (SPPF):} The SPPF module~\cite{he2015spatial} applies sequential $5 \times 5$ max pooling operations to capture multi-scale features efficiently. Compared to parallel pooling branches in standard SPP, SPPF reduces memory allocation overhead by reusing intermediate pooled features.

\subsubsection{Detection Head Architecture}

The detection head follows a Feature Pyramid Network design~\cite{lin2017feature}, fusing features from backbone stages P3, P4, and P5 to enable multi-scale detection. Feature fusion proceeds through:

\begin{enumerate}
    \item \textbf{Top-down pathway:} P5 features are upsampled by $2\times$ and concatenated with P4 features, then processed by 2$\times$ ESPBlock layers. This yields intermediate features at 1/16 scale.
    \item \textbf{Second upsampling:} The 1/16 features are upsampled again and concatenated with P3 features, processed by 2$\times$ ESPBlock layers to produce 1/8 scale features.
    \item \textbf{Bottom-up pathway:} Downsampling pathways mirror the top-down fusion, generating detection features at 1/16 and 1/32 scales through DSConv and concatenation operations.
\end{enumerate}

Detection heads at each scale predict bounding box coordinates, objectness scores, and class probabilities using $1 \times 1$ convolutions. The anchor-free formulation parameterizes bounding boxes as $(x, y, w, h)$ relative to grid cell centers, simplifying post-processing and reducing hyperparameter sensitivity compared to anchor-based methods.

\subsubsection{Parameter and Memory Reduction}

Through systematic architecture pruning, ESPDet-Pico reduces the parameter count from 2.59 million (YOLO11n) to approximately 360,000—an 86\% reduction. Model size decreases from 5.23~MB to 1.06~MB in FP32 precision (79.8\% reduction), enabling the model to fit entirely within ESP32-S3 PSRAM alongside activation buffers. Width and depth scaling factors of 0.50 and 0.25 respectively reduce channel dimensions and layer repetitions while preserving the hierarchical feature extraction structure.

\subsection{Training Methodology}

With the compressed architecture established, training focuses on optimizing detection accuracy under the reduced model capacity constraint. ESPDet-Pico was trained on the grapevine leaf localization dataset described in Section~\ref{sec:dataset}, comprising 328 training images, 82 validation images, and 103 test images. All images contain annotated bounding boxes for individual grape leaf instances in unconstrained vineyard scenes.

\subsubsection{Input Resolution and Rectangular Training}

The model accepts input images at $416 \times 320$ pixel resolution (width $\times$ height). Rectangular training (\texttt{rect=True}) is employed, where images within each batch are resized to maintain their original aspect ratio through letterboxing with black padding. This strategy reduces computational waste on padding pixels compared to square resizing and better preserves object proportions, particularly beneficial for elongated leaves in vineyard imagery.

\subsubsection{Optimization Configuration}

Training employed the AdamW optimizer~\cite{loshchilov2017decoupled} with weight decay regularization to prevent overfitting on the moderate-sized dataset. Key hyperparameters include:

\begin{itemize}
    \item \textbf{Learning rate:} Initial learning rate $\eta_0 = 0.002$ with cosine annealing schedule~\cite{loshchilov2016sgdr} decaying to final learning rate $\eta_f = 0.00002$ (ratio $\eta_f / \eta_0 = 0.01$). Cosine annealing provides smooth learning rate decay without manual tuning of decay milestones.
    \item \textbf{Warmup strategy:} The first 3 epochs employ linear learning rate warmup from $\eta_{warmup} = 0.0001$ to the initial learning rate $\eta_0$, stabilizing early training dynamics.
    \item \textbf{Momentum and weight decay:} Momentum coefficient $\beta_1 = 0.937$, weight decay $\lambda = 0.0005$.
    \item \textbf{Batch size:} 32 samples per batch, balancing training stability with GPU memory utilization.
    \item \textbf{Training duration:} Maximum 1000 epochs with early stopping patience set to 75 epochs, terminating training if validation mAP@50 does not improve for 75 consecutive epochs.
\end{itemize}

Mixed precision training (AMP) was enabled to accelerate training on GPUs with tensor cores, reducing memory footprint and training time without sacrificing numerical stability.

\subsubsection{Loss Function}

The training objective combines three loss components:
\begin{equation}
\mathcal{L}_{\text{total}} = \lambda_{\text{box}} \mathcal{L}_{\text{box}} + \lambda_{\text{cls}} \mathcal{L}_{\text{cls}} + \lambda_{\text{dfl}} \mathcal{L}_{\text{dfl}}
\end{equation}
where $\mathcal{L}_{\text{box}}$ denotes the Complete IoU (CIoU) loss~\cite{zheng2020distance} for bounding box regression, $\mathcal{L}_{\text{cls}}$ represents the binary cross-entropy loss for classification, and $\mathcal{L}_{\text{dfl}}$ is the distribution focal loss for box coordinate refinement. Loss weights are set to $\lambda_{\text{box}} = 7.5$, $\lambda_{\text{cls}} = 0.5$, and $\lambda_{\text{dfl}} = 1.5$. The elevated box loss weight emphasizes precise localization accuracy, critical for subsequent cropping operations in the inference pipeline.

\subsubsection{Data Augmentation Strategy}

Augmentation techniques tailored to vineyard deployment scenarios include:

\begin{itemize}
    \item \textbf{Geometric augmentations:}
    \begin{itemize}
        \item Rotation: $\pm 10^\circ$ (reduced from classification's $\pm 25^\circ$ to preserve localization precision)
        \item Translation: $\pm 10\%$ of image dimensions
        \item Scaling: uniform scaling factor sampled from $[0.5, 1.5]$
        \item Shear: $\pm 2^\circ$
        \item Horizontal and vertical flips: 50\% probability each
    \end{itemize}
    
    \item \textbf{Photometric augmentations:} Conservative color jittering is applied to maintain realistic leaf appearance: hue shift $\pm 1.5\%$, saturation adjustment $\pm 40\%$, value (brightness) adjustment $\pm 40\%$. Minimal hue variation reflects the consistent green coloration of both healthy and diseased grape leaves.
    
    \item \textbf{Mosaic augmentation:} With 100\% probability during the first 50 epochs, four images are randomly sampled, scaled, and blended into a single mosaic image~\cite{bochkovskiy2020yolov4}. Mosaic augmentation increases effective batch size and exposes the model to diverse object scales and spatial configurations. After epoch 50, mosaic is disabled (\texttt{close\_mosaic=50}) to allow fine-tuning on full-resolution images.
    
    \item \textbf{MixUp:} With 10\% probability, pixel-wise linear interpolation between two images and their labels is performed~\cite{zhang2018mixup}, encouraging the model to learn smooth decision boundaries.
\end{itemize}

\subsubsection{Training Convergence}

Training converged after 949 logged epochs, with the best validation mAP@50 achieved at epoch 711. Figure~\ref{fig:espdet_training_curves} illustrates the training dynamics. The validation loss decreased smoothly without oscillations, indicating stable optimization. The cosine learning rate schedule is evident from the gradual decay curve. Early training (epochs 1--30) exhibits rapid performance improvement during the warmup phase, while subsequent training (epochs 30--700) demonstrates steady convergence as the model refines feature representations. After the best checkpoint at epoch 711, validation metrics plateau, triggering early stopping to prevent overfitting. The extended training duration (711 epochs) compared to YOLO11n's faster convergence (327 epochs) reflects the reduced model capacity of ESPDet-Pico, requiring additional training iterations to reach optimal performance.

\subsection{Detection Performance Evaluation}

Model performance is evaluated using mean Average Precision at IoU threshold 0.5 (mAP@50), a standard metric for object detection~\cite{lin2014microsoft}. mAP@50 computes the average precision across all classes, where a detection is considered correct if its Intersection over Union (IoU) with the ground truth bounding box exceeds 0.5.

\subsubsection{ESPDet-Pico Performance Metrics}

On the held-out test set (103 images), ESPDet-Pico achieves:

\begin{itemize}
    \item \textbf{mAP@50:} 56.42\%, demonstrating sufficient localization accuracy for leaf region extraction.
    \item \textbf{mAP@50-95:} 32.29\%, reflecting performance across stricter IoU thresholds (0.5 to 0.95 in 0.05 increments).
    \item \textbf{Precision:} 62.77\%, indicating controlled false positive rate.
    \item \textbf{Recall:} 54.17\%, capturing the majority of visible leaves while maintaining precision.
\end{itemize}

The precision-recall balance favors precision over recall, aligning with the two-stage pipeline design: false negatives (missed leaves) result in lost disease detection opportunities, while false positives (spurious detections) trigger unnecessary classification inference, wasting computational resources. The elevated precision ensures that detected regions predominantly contain leaves rather than background artifacts.

\subsubsection{Deployment Feasibility and Trade-off Justification}

The 79.8\% model size reduction enables full in-memory deployment on ESP32-S3 without external storage access. The 1.06~MB ESPDet-Pico model, combined with activation buffers (approximately 1--2~MB), fits comfortably within the 8~MB PSRAM budget while reserving memory for the classification model and intermediate buffers. In contrast, YOLO11n's 5.23~MB footprint would exceed available memory, necessitating model streaming from flash storage and incurring prohibitive latency exceeding 2~seconds per inference.

The 5.33 percentage point mAP@50 reduction represents an acceptable trade-off for real-time edge deployment. At 56.42\% mAP@50, ESPDet-Pico successfully localizes the majority of visible leaves, providing sufficient region proposals for downstream classification. Missed detections (false negatives) are partially mitigated by temporal redundancy in video stream processing: leaves undetected in one frame may be detected in subsequent frames as camera position or leaf orientation changes. False positives are controlled through precision-weighted aggregation in the multi-leaf inference stage (Chapter~\ref{chap:results}).

Furthermore, the leaf localization task exhibits less stringent accuracy requirements compared to the subsequent disease classification stage. Imperfect localization (e.g., bounding boxes that slightly truncate leaf edges or include small background regions) does not critically impair classification performance, as MobileNetV2 demonstrates robustness to such perturbations during training on real vineyard crops. The primary objective—isolating leaves from complex backgrounds—is achieved reliably by ESPDet-Pico despite its compressed architecture.

\section{Disease Classification Model (MobileNetV2)}
\label{sec:mobilenetv2}

Following leaf localization, each detected leaf region undergoes disease classification to identify the specific pathology present. This stage requires high classification accuracy to ensure reliable disease diagnosis while maintaining computational efficiency for embedded deployment. The classification model must generalize well across the four grape disease categories despite the moderate training dataset size, while fitting within the remaining PSRAM allocation alongside the detection model.

\subsection{Convolutional Neural Network Architecture}

The disease classification model is based on MobileNetV2~\cite{sandler2018mobilenetv2}, a lightweight convolutional neural network architecture specifically designed for resource-constrained mobile and embedded devices. MobileNetV2 achieves computational efficiency through two key architectural innovations: depthwise separable convolutions and inverted residual blocks with linear bottlenecks.

\subsubsection{Depthwise Separable Convolutions}

Standard convolutional layers perform joint spatial and channel-wise filtering, incurring computational cost proportional to $C_{in} \times C_{out} \times k^2 \times H \times W$, where $C_{in}$ and $C_{out}$ denote input and output channels, $k$ is the kernel size, and $H \times W$ represents the spatial dimensions. MobileNetV2 factorizes this operation into two sequential steps:

\begin{enumerate}
    \item \textbf{Depthwise convolution:} Applies a single $k \times k$ filter independently to each input channel, producing $C_{in}$ feature maps. Computational cost reduces to $C_{in} \times k^2 \times H \times W$.
    \item \textbf{Pointwise convolution:} Projects the depthwise features into $C_{out}$ output channels using $1 \times 1$ convolutions, costing $C_{in} \times C_{out} \times H \times W$.
\end{enumerate}

The total computational cost becomes $(C_{in} \times k^2 + C_{in} \times C_{out}) \times H \times W$. For typical configurations where $C_{out} \gg k^2$, this factorization achieves $8$--$9\times$ FLOPs reduction compared to standard convolutions, as previously demonstrated in the ESPDet-Pico backbone (Section~\ref{sec:espdet_pico}).

\subsubsection{Inverted Residual Blocks}

Traditional residual blocks~\cite{he2016deep} employ wide-narrow-wide channel configurations, where intermediate layers have fewer channels than input/output layers to reduce computation. MobileNetV2 inverts this design, using narrow-wide-narrow blocks that expand the channel dimension in intermediate layers through $1 \times 1$ convolutions (expansion ratio typically 6$\times$), apply depthwise convolution in the high-dimensional space, and then project back to a narrow output via $1 \times 1$ linear projection without activation (linear bottleneck). This architecture enables efficient feature transformation while maintaining low-dimensional bottleneck representations suitable for memory-constrained devices.

Skip connections are applied only when input and output dimensions match (stride-1 blocks), allowing gradient flow and facilitating training convergence. The linear bottlenecks prevent information loss from ReLU activation~\cite{sandler2018mobilenetv2}, which would otherwise zero-out negative values in low-dimensional manifolds.

\subsubsection{Model Configuration and Pre-training}

The MobileNetV2 backbone is initialized with weights pre-trained on ImageNet~\cite{deng2009imagenet}, a large-scale visual recognition dataset containing 1.28 million natural images across 1000 object categories. Pre-training provides generic low-level and mid-level visual features (edges, textures, object parts) transferable to the grape disease classification domain, accelerating convergence and improving generalization compared to random initialization.

The input resolution is set to $128 \times 128$ pixels, constrained by ESP32-S3 PSRAM capacity. While MobileNetV2 typically operates at $224 \times 224$ resolution, the controlled nature of the PlantVillage dataset---uniform backgrounds, centered leaves, consistent lighting---enables effective disease recognition at reduced resolution. The reduced input size also decreases memory footprint for activations, allowing the model to fit within the 4~MB PSRAM budget alongside the ESPDet-Pico detection model.

The classification head consists of a global average pooling layer that aggregates the $7 \times 7 \times 1280$ feature maps into a 1280-dimensional feature vector, followed by a dropout layer (dropout rate $p=0.5$) for regularization, and a final fully connected layer with 4 output units (one per disease class). The dropout layer mitigates overfitting by randomly deactivating 50\% of neurons during training, forcing the network to learn robust distributed representations rather than memorizing training-specific patterns.

\subsection{Transfer Learning Strategy}

Adapting ImageNet pre-trained weights to the grape disease classification domain requires careful fine-tuning to leverage generic visual features while learning disease-specific patterns. A two-stage progressive fine-tuning strategy is employed to balance feature transfer with domain specialization.

\subsubsection{Stage 1: Classifier Head Training}

The first stage focuses on training the randomly initialized classification head while keeping the pre-trained MobileNetV2 backbone frozen. Freezing the backbone prevents catastrophic forgetting---the phenomenon where fine-tuning with high learning rates on a small domain-specific dataset destroys useful pre-trained representations~\cite{yosinski2014transferable}. During this stage, only the global average pooling, dropout, and fully connected layers receive gradient updates.

Training duration: 10 epochs with initial learning rate $\eta_1 = 10^{-3}$. The relatively high learning rate enables rapid adaptation of the classification head to the four grape disease categories, while the short training duration prevents overfitting before backbone fine-tuning commences.

\subsubsection{Stage 2: Full Model Fine-tuning}

The second stage unfreezes all layers and fine-tunes the entire network end-to-end. This stage allows the backbone to adapt its feature representations to the specific visual characteristics of grape diseases---leaf discoloration patterns, necrotic spots, chlorotic regions, and fungal structures---while maintaining the general-purpose features learned from ImageNet.

Training duration: 40 epochs with reduced learning rate $\eta_2 = 10^{-4}$. The 10$\times$ learning rate reduction compared to Stage 1 ensures stable fine-tuning of pre-trained weights without destabilizing learned representations. The 40-epoch duration provides sufficient iterations for convergence while preventing overfitting, as validated through early stopping on the validation set.

The two-stage strategy outperforms single-stage end-to-end fine-tuning by establishing a well-adapted classification head before adjusting backbone features, leading to faster convergence and improved generalization~\cite{yosinski2014transferable}.

\subsection{Training Protocol}

\subsubsection{Optimization Configuration}

Both training stages employ the AdamW optimizer~\cite{loshchilov2017decoupled}, which combines adaptive learning rates with decoupled weight decay regularization. AdamW decouples the weight decay term from the gradient-based update, applying L2 regularization directly to weights rather than through gradient computation. This modification improves generalization compared to standard Adam~\cite{kingma2014adam} by preventing weight decay from interfering with adaptive learning rate scaling.

Hyperparameter configuration:
\begin{itemize}
    \item \textbf{Learning rates:} Stage 1: $\eta_1 = 10^{-3}$, Stage 2: $\eta_2 = 10^{-4}$
    \item \textbf{Weight decay:} $\lambda = 10^{-4}$ (L2 regularization coefficient)
    \item \textbf{Momentum parameters:} $\beta_1 = 0.9$, $\beta_2 = 0.999$ (AdamW defaults)
    \item \textbf{Batch size:} 32 samples per batch, balancing training stability with GPU memory utilization
\end{itemize}

\subsubsection{Loss Function}

Training minimizes the cross-entropy loss for multi-class classification:
\begin{equation}
\mathcal{L}_{\text{CE}} = -\frac{1}{N} \sum_{i=1}^{N} \sum_{c=1}^{C} y_{ic} \log(\hat{y}_{ic})
\end{equation}
where $N$ denotes batch size, $C=4$ is the number of disease classes, $y_{ic} \in \{0,1\}$ represents the ground truth label (one-hot encoded), and $\hat{y}_{ic} = \text{softmax}(z_c)$ is the predicted probability for class $c$ of sample $i$. Cross-entropy loss penalizes confident incorrect predictions more heavily than near-boundary errors, encouraging the model to learn discriminative class boundaries.

\subsubsection{Regularization Strategy}

Beyond weight decay and dropout, the data augmentation pipeline described in Section~\ref{sec:dataset} provides implicit regularization by presenting diverse augmented variations of each training sample. The combination of geometric transformations (rotation, scaling, translation) and photometric perturbations (color jitter, brightness adjustment) exposes the model to realistic deployment variability, improving robustness to lighting changes, leaf orientation variations, and camera perspective differences encountered in vineyard environments.

Early stopping monitors validation loss with patience set to 10 epochs. Training terminates if validation loss does not improve for 10 consecutive epochs, preventing overfitting beyond the optimal checkpoint. The model snapshot with lowest validation loss across all epochs is retained as the final model.

\subsubsection{Multi-Seed Experimental Protocol}

To assess model stability and generalization consistency, training is repeated with four different random seeds: 42, 123, 456, and 789. Each seed initializes the random number generator controlling parameter initialization, data shuffling, and stochastic augmentation. This protocol quantifies performance variance attributable to random initialization rather than systematic dataset characteristics, providing confidence intervals for reported accuracy metrics~\cite{henderson2018deep}.

Figure~\ref{fig:mobilenet_training_curves} illustrates representative training dynamics from one experimental run (seed 789). The training and validation losses converge smoothly, indicating stable optimization without oscillations or gradient instability. Validation accuracy plateaus after approximately 35 epochs in Stage 2, triggering early stopping. The learning rate decay from Stage 1 to Stage 2 is evident from the reduced slope of the loss curve in the second training phase.

\subsubsection{Overall Test Set Performance}

The fine-tuned MobileNetV2 model achieves exceptional classification accuracy on the held-out test set (814 images), demonstrating strong generalization despite the moderate training set size. Aggregated results across four independent training runs yield:

\begin{itemize}

    \item \textbf{Macro F1-score:} $0.9980 \pm 0.0010$

\subsection{Post-Training Quantization}

To enable ESP32-S3 deployment, the trained FP32 model undergoes post-training quantization (PTQ) to reduce memory footprint and accelerate inference through integer arithmetic. PTQ converts floating-point weights and activations to 8-bit integers without retraining, making it suitable for deployment scenarios where training on embedded devices is infeasible.

\subsubsection{ESP-PPQ Quantization Framework}

Quantization is performed using ESP-PPQ~\cite{esp_ppq2023}, Espressif's fork of the PPQ (Post-Processing Quantization) framework~\cite{ppq2022}. ESP-PPQ targets the ESP-DL (Espressif Deep Learning) inference library deployed on ESP32-S3 microcontrollers, ensuring hardware compatibility with the ESPDL\_INT8 platform.

The quantization process comprises:

\begin{enumerate}
    \item \textbf{Model export:} The PyTorch model is exported to ONNX format (opset version 13) for framework interoperability.
    \item \textbf{Calibration:} A representative calibration dataset (100 samples per class, 400 total) is forward-propagated through the model to collect activation statistics (min/max ranges for each layer).
    \item \textbf{Quantization configuration:} Per-tensor symmetric quantization with power-of-2 scaling factors is applied. Symmetric quantization maps floating-point values linearly to the integer range $[-128, 127]$, with scale factor $s = \max(|x|) / 127$. Power-of-2 constraints on scale factors enable efficient bit-shift operations on ESP32-S3.
    \item \textbf{INT8 export:} Quantized weights and scale factors are serialized to the ESPDL model format (.espdl), compatible with ESP-DL inference runtime.
\end{enumerate}

\subsubsection{Quantization-Induced Accuracy Degradation}

Post-training quantization introduces rounding errors when mapping continuous floating-point representations to discrete 8-bit integers. However, the MobileNetV2 architecture exhibits strong robustness to INT8 quantization due to its batch normalization layers and inherently quantization-friendly design~\cite{jacob2018quantization}.

The quantized INT8 model maintains test accuracy above 99.5\%, with accuracy degradation below 0.3 percentage points compared to the FP32 baseline. This minimal degradation reflects the high representational capacity remaining after quantization and the redundancy in learned feature representations that accommodate precision reduction.

\subsubsection{Model Size Reduction and Memory Footprint}

The quantization process achieves significant model size reduction:

\begin{itemize}
    \item \textbf{FP32 model:} 8.8~MB (floating-point weights stored as 32-bit values)
    \item \textbf{INT8 quantized model:} 2.3~MB (integer weights stored as 8-bit values)
    \item \textbf{Compression ratio:} 73.9\% size reduction (3.83$\times$ compression)
\end{itemize}

The quantized model, combined with ESPDet-Pico (1.06~MB), totals approximately 3.4~MB for both models, fitting comfortably within the 8~MB PSRAM capacity alongside activation buffers (2--3~MB) and runtime overhead. This memory allocation enables full in-memory deployment without external storage access, eliminating flash read latency and ensuring deterministic inference timing.

The 3.83$\times$ compression from FP32 to INT8 also reduces memory bandwidth requirements during inference, as loading 8-bit weights consumes 75\% less bus bandwidth compared to 32-bit weights. On memory-constrained microcontrollers like ESP32-S3, memory access often dominates inference latency, making quantization beneficial beyond storage savings alone.


\section{Hardware Selection for ESP32-S3-WROOM-1 Dev. Kit}
\label{sec:hardware}

The edge deployment of our two-stage vineyard monitoring system requires a hardware platform that balances computational capability, memory capacity, power consumption, and cost. This section describes the Freenove ESP32-S3 WROOM development board and the underlying ESP32-S3 microcontroller architecture, justifying its selection through comparative analysis with alternative embedded AI platforms.

\subsection{ESP32-S3 System Architecture}

The deployed system is built upon the Freenove ESP32-S3 WROOM development board~\cite{freenove2024esp32s3}, a comprehensive hardware platform centered around Espressif's ESP32-S3-WROOM-1 module. The ESP32-S3-WROOM-1 integrates an ESP32-S3 dual-core System-on-Chip (SoC), 8~MB octal SPI PSRAM, and 16~MB quad SPI flash memory in a compact surface-mount module, simplifying hardware integration and reducing PCB complexity for edge deployments.

The ESP32-S3 SoC, designed specifically for embedded AI and IoT applications~\cite{espressif2022esp32s3}, features an Xtensa LX7 dual-core processor operating at up to 240~MHz, providing sufficient computational throughput for real-time inference of lightweight neural networks. Unlike earlier ESP32 variants (ESP32 and ESP32-S2), the ESP32-S3 includes vector instructions and AI acceleration extensions tailored for convolutional neural network operations, including 16-bit and 8-bit integer multiply-accumulate (MAC) instructions that accelerate quantized inference. The dual-core architecture enables parallel execution of inference and system management tasks, with one core dedicated to neural network computation while the other handles camera acquisition, WiFi communication, and system housekeeping.

The memory subsystem of the ESP32-S3 consists of a three-tier hierarchy optimized for resource-constrained edge deployment:

\begin{enumerate}
    \item \textbf{Internal SRAM (512~KB):} High-speed on-chip memory used for critical runtime data, including the inference engine stack, temporary buffers, and frequently accessed activation tensors. SRAM access incurs minimal latency (single-cycle for sequential access) but is limited in capacity, necessitating careful memory management.
    
    \item \textbf{External PSRAM (8~MB):} Off-chip pseudo-static RAM connected via the SPI interface, providing bulk storage for model weights, input/output buffers, and large activation maps. While slower than internal SRAM (approximately 4--8~cycles per access depending on cache behavior), PSRAM capacity is sufficient to hold both the ESPDet-Pico detection model (1.06~MB), the MobileNetV2 classification model (2.3~MB), and all intermediate activations (2--3~MB) entirely in memory. This eliminates the need for model streaming from flash storage during inference, ensuring deterministic latency.
    
    \item \textbf{Flash Memory (16~MB):} Non-volatile storage used for firmware, model binaries, configuration data, and boot images. Although flash access is significantly slower than PSRAM (read latency of 10--50~$\mu$s per cache miss), models and executables remain persistent across power cycles. The ESP-DL framework supports direct execution of quantized models from flash via memory-mapped I/O, but for latency-critical applications, models are copied to PSRAM during initialization~\cite{esp_dl}.
\end{enumerate}

The ESP32-S3 integrates several peripherals essential for vineyard monitoring applications. The camera interface supports parallel DVP (Digital Video Port) connectivity with 8-bit or 16-bit data width, enabling direct attachment of low-cost image sensors such as the OV2640 (2~MP) or OV2660 (2~MP) without requiring external image signal processors. The Freenove development board provides a dedicated 24-pin camera connector compatible with standard ESP32-CAM modules and standalone image sensors, facilitating rapid prototyping and deployment. This integration simplifies system design and reduces power consumption by avoiding USB or MIPI camera interfaces that would require additional interface chips and increase system latency.

The onboard WiFi (802.11 b/g/n) and Bluetooth Low Energy (BLE 5.0) radios enable wireless communication for remote monitoring and data logging, critical for distributed vineyard deployments where wired connectivity is impractical. The Freenove board includes a ceramic antenna with optimal radiation pattern for outdoor agricultural environments, eliminating the need for external antenna modules. Additionally, the board exposes GPIO pins for sensor expansion, I2C/SPI interfaces for environmental sensors (temperature, humidity, soil moisture), and a MicroSD card slot for local data logging when network connectivity is unavailable.

Power consumption is a key consideration for agricultural edge devices, particularly when deployed in remote vineyard plots with solar or battery power. The ESP32-S3 supports dynamic voltage and frequency scaling (DVFS), enabling power management across multiple operating modes. In active inference mode at 240~MHz with WiFi enabled, the system consumes approximately 200--300~mW, while deep sleep modes reduce consumption to 7--10~$\mu$W, allowing battery-powered operation with periodic wake-up for inference and transmission. This flexibility aligns with the duty-cycled operation typical of agricultural monitoring systems, where continuous inference is unnecessary, and power budgets are constrained~\cite{ferrandez2018precision, talavera2017review}.

The Freenove ESP32-S3 board provides a deployment-ready platform for real-time two-stage disease detection, balancing computational capability, development convenience, and the practical demands of vineyard field deployment.

\section{Edge Deployment of Integrated Lightweight Neural Networks on ESP32-S3}
\label{sec:deployment}

The deployment of the two-stage vineyard monitoring system on the ESP32-S3 microcontroller requires careful orchestration of memory management, model loading strategies, and inference pipeline implementation to achieve real-time performance within severe resource constraints. This section documents the architectural decisions, optimization strategies, and performance characteristics of the deployed system, reflecting lessons learned through extensive iterative prototyping across multiple firmware revisions.

\subsection{Memory Management Architecture}

Effective memory management is critical for embedded deep learning deployment, where model weights, activation buffers, and input/output tensors must coexist within fixed SRAM (512~KB) and PSRAM (8~MB) capacities. The ESP32-S3 platform presents unique challenges due to its heterogeneous memory hierarchy, requiring strategic allocation decisions to maximize performance while preventing memory fragmentation that can cause system instability.

\subsubsection{Model Storage and Loading Strategy}

Through extensive experimentation across nine firmware iterations (versions v8--v16), multiple model loading strategies were evaluated to identify the optimal approach for simultaneous deployment of ESPDet-Pico (detection) and MobileNetV2 (classification) models. The evaluated strategies included:

\textbf{Dedicated Partition Loading (v12):} Models stored in custom flash partitions (\texttt{espdet\_model} @ 0x600000) and loaded via \texttt{MODEL\_LOCATION\_IN\_FLASH\_PARTITION}. This approach encountered cache coherency issues and MMU mapping conflicts when accessing partition data, resulting in unpredictable model loading failures and system crashes.

\textbf{Memory-Mapped Access (v8):} Direct memory-mapped I/O with \texttt{param\_copy=false}, avoiding PSRAM copy overhead. While theoretically efficient, this strategy proved unreliable due to flash cache eviction under memory pressure from camera DMA buffers, causing inference failures when model parameters were evicted from cache.

\textbf{Chunked PSRAM Copy (v9):} Incremental model loading to PSRAM in 16~KB chunks to avoid large contiguous allocations. Although this mitigated allocation failures, the overhead of repeated partition reads (10--50~$\mu$s per read) and fragmented PSRAM layout degraded inference latency by 15--20\%.

\textbf{RODATA Embedding with PSRAM Mirror (v10--v11):} Models embedded in firmware binary via linker scripts, placed in \texttt{.rodata} section, with optional PSRAM mirroring (\texttt{param\_copy=true}). This approach eliminated partition read overhead but introduced initialization-order dependencies that conflicted with camera driver allocation patterns.

The final production strategy (v17, current deployment) employs \textbf{RODATA Embedding with Direct Flash Access} (\texttt{MODEL\_LOCATION\_IN\_FLASH\_RODATA}), where both models are compiled into the firmware binary as constant arrays via GCC's \texttt{\_binary\_*\_start/\_binary\_*\_end} symbols. Models remain in flash memory and are accessed directly through the instruction cache without PSRAM copy, reducing initialization time from 1,200~ms (chunked copy) to 180~ms while conserving PSRAM for activation buffers. The ESP-DL inference engine internally caches frequently accessed weight tiles in SRAM (up to 64~KB) through a least-recently-used (LRU) eviction policy, balancing flash access latency with memory capacity.

\subsubsection{Initialization Order and PSRAM Fragmentation}

A critical discovery (v13) revealed that \textbf{model initialization must precede camera initialization} to prevent catastrophic PSRAM fragmentation. The ESP32 camera driver allocates large DMA buffers for frame capture (2$\times$ 640$\times$480 JPEG buffers $\approx$ 180~KB total) at initialization, fragmenting the PSRAM heap into non-contiguous regions. Subsequent attempts to allocate model activation buffers (2--3~MB contiguous blocks) fail due to insufficient contiguous memory, despite adequate total free PSRAM.

The enforced initialization sequence is:
\begin{enumerate}
    \item \textbf{Detection model loading:} ESPDet-Pico initialized first, allocating activation buffers (1.2~MB) for 416$\times$320 input in a contiguous PSRAM region.
    \item \textbf{Classification model loading:} MobileNetV2 initialized second, allocating activation buffers (800~KB) and a persistent 128$\times$128$\times$3 RGB input buffer (49~KB) in PSRAM.
    \item \textbf{Camera driver initialization:} Camera interface initialized last, allocating remaining PSRAM for DMA framebuffers and JPEG encode buffers.
\end{enumerate}

Violating this order (e.g., initializing camera first) results in allocation failure during model loading with error code \texttt{ESP\_ERR\_NO\_MEM}, necessitating system reboot. This constraint is documented in firmware comments and enforced through assertion checks in production code.

\subsubsection{Buffer Allocation and Reuse}

To minimize runtime memory allocation overhead and prevent heap fragmentation during continuous operation, the inference pipeline employs a \textbf{single-allocation, zero-copy buffer strategy}:

\begin{itemize}
    \item \textbf{Classification input buffer (49~KB):} A single 128$\times$128$\times$3 RGB888 buffer is allocated in PSRAM during classifier initialization and reused across all detected leaf regions within a frame. This eliminates repeated \texttt{malloc}/\texttt{free} calls (previously 5--10 per frame in v16), which caused 200~$\mu$s allocation overhead per crop and accumulated heap fragmentation over hours of operation.
    
    \item \textbf{Camera framebuffers (180~KB):} Two framebuffers allocated by the camera driver in PSRAM via \texttt{CAMERA\_FB\_IN\_PSRAM} configuration. Buffers are managed by the camera driver's double-buffering scheme: one buffer captures the next frame while the other undergoes processing, enabling pipelined operation without explicit synchronization.
    
    \item \textbf{JPEG decode buffer (900~KB):} Decoded RGB888 frames (640$\times$480$\times$3) are allocated dynamically by the \texttt{dl::image::sw\_decode\_jpeg()} software decoder. This temporary allocation is freed immediately after detection inference completes, as leaf crops are extracted directly from the decoded buffer without intermediate storage. Attempts to reuse a persistent decode buffer (v15) were abandoned due to RGB-to-JPEG re-encoding overhead (80~ms per crop) when saving intermediates.
    
    \item \textbf{Detection/classification activation buffers (2~MB total):} Intermediate feature maps for convolutional layers are allocated by the ESP-DL memory manager during model initialization and persist throughout execution. The memory manager implements a static allocation plan computed offline during quantization, minimizing runtime allocation calls and enabling deterministic memory usage profiling.
\end{itemize}

The elimination of dynamic allocation in the inference loop (v17 vs v16) reduced per-frame memory management overhead from 1,400~$\mu$s to negligible (\textless 10~$\mu$s), contributing to the 3$\times$ throughput improvement observed in the production system.

\subsection{Inference Pipeline Implementation}

The complete inference pipeline orchestrates five sequential stages: camera acquisition, JPEG decoding, leaf detection, region extraction with preprocessing, and disease classification, followed by cross-leaf aggregation for frame-level diagnosis. Each stage is optimized for minimal latency and memory footprint while maintaining modularity for independent testing and validation.

\subsubsection{Camera Acquisition and Image Decoding}

Image acquisition begins with the OV2640 or OV3660 camera module configured for VGA resolution (640$\times$480) with on-chip JPEG compression. The camera's hardware JPEG encoder reduces wireless transmission overhead (critical for LoRaWAN deployment where payloads are limited to 51--222 bytes per uplink~\cite{adelantado2017understanding}) and minimizes SPI bus bandwidth between camera and ESP32-S3 (20~MHz SCLK, 8-bit parallel DVP interface).

Camera configuration prioritizes deployment robustness:
\begin{itemize}
    \item \textbf{Pixel format:} \texttt{PIXFORMAT\_JPEG} with quality setting 12 (scale 0--63, lower = higher quality), balancing compression ratio ($\sim$10:1) with minimal blocking artifacts that could degrade detection accuracy.
    \item \textbf{Automatic exposure/white balance:} Enabled via sensor control registers (\texttt{set\_exposure\_ctrl}, \texttt{set\_whitebal}, \texttt{set\_awb\_gain}) to adapt to varying vineyard lighting conditions (sunlight, cloud cover, shadows) without manual recalibration.
    \item \textbf{Frame buffering:} Dual-buffer mode (\texttt{fb\_count=2}) enables capture-while-processing: the camera populates buffer~1 while the inference pipeline processes buffer~0, achieving near-zero capture latency overhead.
\end{itemize}

Captured JPEG frames (typical size 30--80~KB for VGA at quality~12) are decoded to RGB888 format using ESP-IDF's software JPEG decoder (\texttt{dl::image::sw\_decode\_jpeg()}) since the ESP32-S3 lacks hardware JPEG decoding acceleration (unlike ESP32-S2/S3 variants with dedicated JPEG engines). Decode latency averages 65--85~ms per VGA frame, dominated by Huffman decoding and IDCT computation. The decoder writes directly to a heap-allocated RGB888 buffer (640$\times$480$\times$3 = 921,600 bytes) in PSRAM, avoiding intermediate YUV conversions.

\subsubsection{Leaf Detection and Bounding Box Extraction}

The decoded RGB888 frame undergoes ESPDet-Pico detection inference to localize individual leaf regions. Preprocessing resizes the 640$\times$480 input to 416$\times$320 via bilinear interpolation with letterbox padding (gray fill, RGB=[127,127,127]) to preserve aspect ratio and maintain detection accuracy on elongated leaves. The resized input is normalized using ImageNet statistics ($\mu=[0.485, 0.456, 0.406]$, $\sigma=[0.229, 0.224, 0.225]$) to align with the model's training distribution.

Detection inference produces a list of bounding boxes with associated confidence scores and class IDs (single class: \texttt{grape\_leaf}). Post-processing applies confidence thresholding (threshold $\tau=0.25$, tuned empirically to balance recall and computational cost) and non-maximum suppression (NMS with IoU threshold 0.45) to eliminate duplicate detections of overlapping leaves. Detected boxes are sorted by descending confidence, and the top-$K$ detections ($K=10$ in production) are forwarded to the classification stage. This top-$K$ filtering strategy prevents classification of low-confidence false positives (background clutter, stems, trellises) while limiting worst-case inference latency to $K \times T_{\text{classify}}$, where $T_{\text{classify}} \approx 530$~ms per leaf.

Bounding box coordinates are mapped from the 416$\times$320 detection space back to the original 640$\times$480 frame space via inverse letterbox transformation:
\begin{equation}
x_{\text{orig}} = \frac{(x_{\text{det}} - \text{pad}_x) \times W_{\text{orig}}}{W_{\text{det}} - 2\text{pad}_x}, \quad
y_{\text{orig}} = \frac{(y_{\text{det}} - \text{pad}_y) \times H_{\text{orig}}}{H_{\text{det}} - 2\text{pad}_y}
\end{equation}
where $\text{pad}_x$ and $\text{pad}_y$ denote horizontal and vertical padding widths introduced during letterbox resizing. This transformation ensures that cropped leaf regions align precisely with the original RGB888 frame for downstream classification.

\subsubsection{Region Cropping and Classification Preprocessing}

For each detected bounding box, the corresponding leaf region is extracted from the 640$\times$480 RGB888 frame and resized to 128$\times$128 to match MobileNetV2's input requirements. The cropping operation implements \textbf{square expansion with letterbox padding}: the rectangular bounding box is expanded to a square centered on the box's midpoint, with side length equal to $\max(\text{width}, \text{height})$. This preserves the leaf's aspect ratio and prevents distortion that could impair classification accuracy, particularly for elongated or irregularly shaped leaves.

The resizing algorithm employs \textbf{nearest-neighbor interpolation} rather than bilinear interpolation to minimize computation:
\begin{equation}
I_{\text{128}}[y, x] = I_{\text{frame}}[\lfloor y \times s_y \rfloor, \lfloor x \times s_x \rfloor]
\end{equation}
where $s_x = W_{\text{bbox}} / 128$ and $s_y = H_{\text{bbox}} / 128$ denote scaling factors. Nearest-neighbor interpolation reduces per-crop preprocessing time from 12~ms (bilinear) to 4--6~ms (nearest), a 50--60\% reduction critical when processing 10 leaves per frame. The minor degradation in image smoothness (aliasing artifacts on leaf edges) does not significantly impact classification accuracy, as MobileNetV2 was trained on similar preprocessing during offline augmentation.

Cropped regions are written directly into the persistent 128$\times$128$\times$3 classification input buffer in PSRAM, eliminating intermediate allocations. Pixels outside the original frame bounds (due to square expansion) are filled with gray padding (RGB=[127, 127, 127]) approximating ImageNet's mean pixel value, ensuring consistent normalization behavior.

\subsubsection{Disease Classification Inference and Softmax Decoding}

The cropped and resized 128$\times$128 RGB888 leaf image undergoes MobileNetV2 classification inference. The model's input tensor pointer is set to the classification buffer (\texttt{input->set\_element\_ptr(input\_buffer\_128x128)}), and inference is triggered via \texttt{model->run()}, executing the quantized INT8 forward pass through 17 inverted residual blocks.

The model outputs a 4-dimensional INT8 logit vector representing unnormalized class scores for \texttt{Black\_rot}, \texttt{Esca}, \texttt{Healthy}, and \texttt{Leaf\_blight} (ordered alphabetically per PyTorch \texttt{ImageFolder} class indexing). The INT8 logits must be dequantized to floating-point before probability interpretation:
\begin{equation}
\text{logit}_{\text{float}}^{(c)} = \text{logit}_{\text{int8}}^{(c)} \times 2^{e}
\end{equation}
where $e$ denotes the quantization exponent (typically $e \in [-5, -8]$ for MobileNetV2 layers) embedded in the model's tensor metadata. The exponent is retrieved via \texttt{output->exponent}, and the scale factor $s = 2^e$ is computed using the \texttt{DL\_SCALE(e)} macro.

Dequantized logits are converted to probabilities via softmax activation:
\begin{equation}
p^{(c)} = \frac{\exp(\text{logit}^{(c)} - \max_j \text{logit}^{(j)})}{\sum_{k=1}^{C} \exp(\text{logit}^{(k)} - \max_j \text{logit}^{(j)})}
\end{equation}
where the $\max$ subtraction ensures numerical stability by preventing overflow in the exponential computation. The predicted class corresponds to $\arg\max_c p^{(c)}$, returned alongside the maximum probability as the classification confidence.

Timing profiling reveals that classification inference decomposes into: (1)~tensor setup (8--12~$\mu$s, pointer assignment), (2)~forward pass (520--550~ms, dominated by depthwise convolutions), and (3)~softmax post-processing (80--100~$\mu$s). The forward pass accounts for 99.8\% of classification latency, with depthwise convolutions executing in INT8 arithmetic on the Xtensa LX7 SIMD units.

\subsubsection{Multi-Leaf Aggregation for Frame-Level Diagnosis}

Since vineyard images typically contain multiple leaves (5--15 visible leaves per 640$\times$480 frame in field trials), frame-level disease assessment requires aggregating predictions across all detected instances. Three aggregation strategies were implemented and evaluated:

\textbf{1. Detection-Confidence Weighting (Baseline):} Each leaf's class probabilities are weighted by its detection confidence $c_{\text{det}}$:
\begin{equation}
p_{\text{frame}}^{(c)} = \frac{\sum_{i=1}^{N} c_{\text{det}}^{(i)} \cdot p_i^{(c)}}{\sum_{i=1}^{N} c_{\text{det}}^{(i)}}
\end{equation}
where $N$ denotes the number of detected leaves, and $p_i^{(c)}$ represents leaf $i$'s probability for class $c$. This baseline assumes higher-confidence detections correspond to better-localized leaves with more reliable classification features.

\textbf{2. Entropy-Based Uncertainty Weighting:} Classification entropy quantifies prediction uncertainty:
\begin{equation}
H_i = -\sum_{c=1}^{C} p_i^{(c)} \log p_i^{(c)}
\end{equation}
Leaves with low entropy (confident predictions, e.g., $H \approx 0$ when one class dominates) receive higher weight than high-entropy ambiguous predictions. The aggregation weight becomes:
\begin{equation}
w_i = c_{\text{det}}^{(i)} \cdot \left(1 - \frac{H_i}{H_{\max}}\right)
\end{equation}
where $H_{\max} = \log C$ normalizes entropy to [0, 1]. This approach downweights leaves near class boundaries (e.g., Black Rot vs Esca confusion) exhibiting high classification uncertainty.

\textbf{3. Hybrid Spatial-Quality Weighting:} Bounding box geometry provides additional quality indicators:
\begin{itemize}
    \item \textbf{Relative size:} $r_{\text{size}} = A_{\text{bbox}} / A_{\text{frame}}$, penalizing excessively small (noise) or large (misdetections) boxes via a triangular membership function centered at 0.05--0.15.
    \item \textbf{Aspect ratio:} $r_{\text{aspect}} = \max(w, h) / \min(w, h)$, penalizing extremely elongated boxes (stems, trellis wires) with ideal ratio 1.0--1.5 for grape leaves.
    \item \textbf{Centrality:} $d_{\text{center}} = \|(x_c, y_c) - (W/2, H/2)\| / \sqrt{W^2 + H^2}$, downweighting edge-positioned leaves that may be partially occluded or distorted by camera lens aberration.
\end{itemize}

The combined quality score $q_i \in [0, 1]$ multiplies the detection-entropy weight:
\begin{equation}
w_i^{\text{hybrid}} = c_{\text{det}}^{(i)} \cdot \left(1 - \frac{H_i}{H_{\max}}\right) \cdot q_i
\end{equation}

Comparative evaluation on field test data (Section~\ref{sec:aggregation_strategies}) demonstrates that hybrid weighting improves frame-level classification accuracy by 3.2 percentage points over baseline detection-confidence weighting, reducing false positives from background clutter and partially occluded leaves.

\subsection{Deployment Validation}

The complete inference pipeline underwent extensive field validation across 200+ capture cycles spanning diverse vineyard conditions. For a typical frame containing 7 detected leaves (median from field deployment), the end-to-end inference latency totals approximately 4.2 seconds, enabling 0.24 FPS throughput. The system demonstrates linear scaling with leaf count: classification dominates execution time (42.8\% of total latency for 7 leaves), while vision preprocessing (camera capture, JPEG decode) and aggregation contribute minimal overhead (<13\% combined).

Memory profiling confirms stable operation with 4.2~MB PSRAM free post-initialization and zero memory leakage over 8-hour continuous operation, validating the single-allocation zero-copy buffer strategy. Power measurements using a Joulescope JS220 precision analyzer reveal 245~mW active power consumption during inference and 8.2~$\mu$W in deep sleep. With 5-minute duty-cycled operation (1.4\% active time), the system achieves 3.4~mW average power consumption, enabling solar-powered autonomous deployment with 14+ days battery backup.
